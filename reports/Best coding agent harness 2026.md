# No harness wins; failure modes decide

The evidence does not support naming one best AI coding agent harness in late 2026. The official Terminal-Bench 4.0 board has no model listed under two agents, so it cannot measure a harness effect at all, and Factory's claim that Droid leads comes from a vendor-run study whose margin is smaller than the gap a reasoning-effort setting produces on its own. Controlled same-model studies find pass-rate differences of about 0 to 8 points, mostly statistically unresolved, against cost differences of 3x to 40x, while switching models inside one harness moves Terminal-Bench 4.0 by about 40 to 50 points. The working rule is to choose the model for pass rate and the harness for cost, unless tight context or a specific failure (output cap, idle loop, timeout, empty patch) is in play. What makes a harness good is therefore measurable and narrower than the marketing: it avoids mechanical failures, keeps its prefix cacheable, drops old tool output before summarising, checks completion with evidence instead of the transcript, and gives repository content no authority before consent. ox has one reproducible advantage, a first request of about 2,070 tokens against 10,000 to 17,000 for Codex, Hermes and Claude Code in its own recorder test, and no evidence at all that it solves more tasks or costs less per task than any rival. The honest claim is "lightest first request among the agents ox has measured, with the strictest opt-in proof pipeline we found documented, not yet benchmarked on real tasks." The next work is a consent gate for `.mcp.json`, which still launches commands from an untrusted repository, then real cache stability, then the same-model experiment that nothing else can substitute for.

The ox findings describe commit `e14b014` (4 Nov 2026). The source audit was done at `3c6a1a1`; four commits landed during this research and fixed several of its findings, and those fixes are marked below. File references are repo-relative, and line numbers come from the audit commit, so they may have shifted slightly.

## Same-model tests shrink the harness gap to single digits, while cost gaps reach 40x

Three kinds of number circulate, and they disagree because they measure different things. The official board compares model and harness as a bundle. Its top rows are Opus 5.5 with Claude Code at max effort at **64.8% ±3.1**, Sonnet 5.5 with Claude Code at 61.8% ±2.9, and GPT-6 Astra and GPT-6.1 Sol with Codex both at 58.2%, the latter at about $0.6k for a full run against $4.7k for the Opus row ([Snorkel](https://snorkel.ai/leaderboard/terminal-bench/)). The 23 rows contain no model under two agents, and whether rows are maintainer-run or self-submitted could not be determined from the page. The last official board with same-model pairs is Terminal-Bench 2.1, where the native harness minus neutral Terminus 2 comes to +3.4, +5.1, +2.8, −8.1 and +0.2 points across five models (my arithmetic from [Snorkel 2.1](https://snorkel.ai/leaderboard/terminal-bench-2-1/)). Native is not uniformly better.

Factory's 23–28 October study is the only recent same-model comparison across commercial harnesses. On Opus 5.5 it reports Droid 65.2%, Cursor 62.1%, OpenCode 62.1%, Devin 59.6% and Claude Code 57.6%. On GPT-6.1 Sol it reports Droid 57.6%, Codex 54.0%, OpenCode 51.0% and Devin 45.0% ([Factory](https://factory.com/articles/terminal-bench-agent-comparison)). The study is vendor-run, gives no confidence intervals, and has no independent re-run that this research could find. Its permissions were set to skipped, so it says nothing about behaviour under safety controls. **The same Claude Code and Opus 5.5 pair scores 64.8 on the board at max effort and 57.6 in Factory's run at high reasoning. That 7.2-point configuration gap is more than double Droid's 3.1-point lead over the next harness, and Droid's 65.2 sits inside the board's interval for Claude Code.** The two runs are not a fair head-to-head either, because effort differs, and no fair one exists.

Controlled work points the same way, with one exception. Liu and Han found Claude Code and mini-SWE-agent within 5 points on 447 SWE-bench Verified tasks; on 45 hard tasks, swapping harness flips about 13% of outcomes, **the same rate as rerunning the same harness**, and cost varies up to 3x, driven by fixed preamble times step count ([arXiv 2610.04433](https://arxiv.org/abs/2610.04433)). Arjmandi's private 80-task paired set found native versus neutral at −1.25 and +1.25 points with intervals spanning zero, although strata split sharply on Opus: −9.0 on repository tasks and +23.7 on contest tasks, in a post hoc split ([arXiv 2609.11987](https://arxiv.org/abs/2609.11987)). Vats and Golev found paired gaps of 0 to 8 points and up to **40x differences in tokens per solved task**, with failure patterns that repeat per harness across models ([arXiv 2607.22585](https://arxiv.org/abs/2607.22585)). HarnessTax reports Fable 5 at 97.8, 96.7 and 96.7 on SWE-bench Lite in Claude Code, Codex and Pi, at $1.33, $0.89 and $0.67 a run ([Digital Applied](https://www.digitalapplied.com/blog/coding-agent-harness-cost-harnesstax-same-model-5x); the primary was truncated when fetched). The exception is tight context: Lewis changed only context handling and stall response, under a 20,480-token window, and raised complete solutions from 43 to 72 of 169 tasks, while with a wide window the gaps closed ([arXiv 2608.26218](https://arxiv.org/abs/2608.26218)).

The uncontrolled view looks larger: a median 13.6-point range within a model across harnesses on Terminal-Bench 2.0 ([arXiv 2606.20683](https://arxiv.org/pdf/2606.20683)). That overstates cause. A maximum-minus-minimum range grows with the number of harnesses tried, one prominent submission is reportedly unverified, and task bugs interact with harnesses: repairing 28 tasks between 2.0 and 2.1 reversed Claude Code against Terminus 2 on Opus 4.6, per a search extract of the [2.1 board](https://snorkel.ai/leaderboard/terminal-bench-2-1/). Controlled studies, on the other hand, run mostly on older and easier suites, so they could understate effects on long terminal tasks. No variance decomposition exists, and the widely repeated "70% of performance lives outside the model" has no measurement behind it in anything retrieved.

The benchmarks themselves are shaky. OpenAI stopped reporting SWE-bench Verified after finding at least 59.4% of 138 audited tasks had tests rejecting correct solutions, as reported secondhand because the primary returned 403 ([LeCompute](https://lecompute.fr/en/runtimes/crise-mesure-agents-codage/)), and on 8 July said 30% of SWE-Bench Pro tasks were broken, retracting its earlier recommendation ([OpenAI](https://x.com/OpenAI/status/2074972179385720836)). OpenAI competes on these scores, and the Pro retraction came the day before a launch in which its model trailed on Pro, so the motive is open to question even though the task defects were reported in detail. METR, independently, found merge rates about 24 points below grader scores ([METR](https://metr.org/notes/2026-03-10-many-swe-bench-passing-prs-would-not-be-merged-into-main/)). A firm selling RL environments moved Sonnet 5.5 from 62.8% to 89.2% on 65 Terminal-Bench 4 tasks after fixing unstated grading rules and cheats ([Preference Model](https://preferencemodel.com/blog/terminal-bench-4-is-saturated/)). That is one model and an interested party, but it is the only such audit of the current reference suite found, and it deserves replication. **Statistical power adds a further limit: at Liu and Han's figures, 45 tasks detect a 13-point gap only about half the time, and 447 tasks resolve about 5 points. By extrapolation, a 66-task suite at three trials cannot settle a 3-point lead.**

### Context and tokens: triggers run from 50% to 97%, and nobody has tested which is right

Harness compaction triggers run from 50% (Gemini CLI, Hermes) to about 97% of a 1M window (Claude Code), and **no published study compares trigger points on coding tasks**. Three designs now avoid destructive truncation: spill to file with a preview (Claude Code, Cursor, Hermes, opencode, Gemini), keep raw output inside a program (Droid Script), and start a fresh window (Amp Handoff, an in-development Codex `token_budget`). Droid publishes the best cache telemetry: 98% median request cache read and 91.5% token-weighted over 20.4M CLI requests ([Factory](https://factory.com/news/frontier-harness)), vendor-reported and unaudited. Claude Code documents the most rigorous practice, treating hit-rate drops as incidents ([Anthropic](https://claude.dev/blog/lessons-from-building-claude-code-prompt-caching-is-everything/)), but an independent July capture found version 2.1.207 rewriting about 37–50K tokens mid-task while OpenCode's prefix stayed byte-identical ([Systima](https://systima.ai/blog/claude-code-vs-opencode-token-overhead)). That version is about 100 releases old, and its 32.8K floor sits at twice the roughly 16.7K measured later, so its numbers should not be read as current.

Floor size alone misleads. In Systima's FizzBuzz task, Claude Code's 3 batched requests used less input than OpenCode's 9. Across configurations that all passed one task, cumulative input varied **12.8x** (293,882 to 3,752,134 tokens), attributed to refetching ([arXiv 2608.16630](https://arxiv.org/pdf/2608.16630)). Cost is floor times steps, discounted by cache hits, so request count and hit rate matter as much as floor.

### Tools: fewer definitions up front, and edit formats that matter mainly for weaker models

Leaders now send far fewer definitions at the start: Droid moved from 11 tools to 2 plus a script tool, and Claude Code defers MCP by default. Fan and colleagues found bash-capable models do well bash-only at substantially lower cost, in the most systematic component study available, though only its abstract could be read ([arXiv 2609.20804](https://arxiv.org/abs/2609.20804)). On edit format, Cursor and Factory assign per model. The strongest public claim, hashline's +15 points across 16 models, comes from its author ([Bölük](https://stencil.so/blog/the-harness-problem)) and failed a small partial replication in which between-model gaps exceeded between-format gaps ([nwyin](https://dev.to/nwyin/hashline-vs-replace-does-the-edit-format-matter-15n2)). Retrieval has the best warning in the field: Cursor's semantic search gained 12.5% offline and **0.3% online** in code retention, 2.6% on repositories of 1,000 or more files ([Cursor](https://cursor.com/blog/semsearch)). I found no independent head-to-head for code graphs on a public benchmark, and Aider's repo map has no controlled measurement.

### Subagents and missions: more cost, flat accuracy, and one reliable failure

Harnesses have converged on fresh-context children that return a summary, and they diverge on files. Stanford's DeLM paper is the strongest test of native subagents, and its authors propose a competitor. Subagents cost **1.5 to 2.9x** the single agent, with accuracy flat or lower, and on DeepSWE with Opus 5.5 accuracy fell from 71.67% to 50%, as parents held the final commit waiting on children cut off by an idle limit and ended with an empty patch or timeout ([arXiv 2606.10662](https://arxiv.org/pdf/2606.10662)). Coupling decides safety: on a tightly coupled migration Codex passed 2 of 6 decomposed and 3 of 3 single-worker, while on independent fixes both passed 3 of 3 and Claude ran 30% faster with subagents, in cells the authors call exploratory ([arXiv 2608.16630](https://arxiv.org/pdf/2608.16630)).

Project-scale results show what is reachable, not what is efficient. Anthropic's 16-agent compiler cost just under $20,000 with no single-agent arm ([Anthropic](https://www.anthropic.com/engineering/building-c-compiler)). Cursor's hundreds-of-agents run has no control and reports that locks reduced 20 agents to the throughput of 2 or 3 ([Cursor](https://cursor.com/blog/scaling-agents)). Factory's Missions publish telemetry, not outcomes: median about 2 hours and 12x the tokens of a session, with no success rate ([Factory](https://factory.com/news/missions)), and its docs still call the cost and quality trade-off unresolved. Cognition's position, single-threaded writes with extra agents contributing analysis, is a vendor opinion, yet it is the one this evidence best supports ([Cognition](https://cognition.com/blog/multi-agents-working)).

### Memory: short human rules beat every system tested on coding work

ETH Zurich and LogicStar found LLM-generated instruction files **lowered resolution slightly and raised cost by 20–23%**, developer-written files raised resolution 2.4% (not significant) at up to 19% more cost, and repository overviews did not help ([arXiv 2602.11988](https://arxiv.org/pdf/2602.11988)). An observational study of 124 PRs found faster runs and fewer output tokens with AGENTS.md ([arXiv 2601.20404](https://arxiv.org/abs/2601.20404)), so the direction on cost is contested, though the controlled result carries more weight. In a separate experiment, a correct written standard drove the better form 100% of the time, code examples alone 33%, and **a stale standard demanding the worse form 0%** ([arXiv 2608.16630](https://arxiv.org/pdf/2608.16630)). VibeMemBench found eleven of twelve pairings of memory systems and solvers failed to beat memory off, with 69.3% of failures traced to how a record was rendered, chiefly instruction pollution from raw transcripts ([arXiv 2609.23570](https://arxiv.org/html/2609.23570)). That test excludes Claude and GPT solvers. LOCOMO-style recall scores do not predict any of this, and the benchmark has unscorable items and a full-context baseline that beats leading systems ([arXiv 2604.10981](https://arxiv.org/pdf/2604.10981); [Zep](https://www.getzep.com/blog/lies-damn-lies-statistics-is-mem0-really-sota-in-agent-memory/)).

### Verification: false completion is common and mechanical checks work best

False success was 75.8% of failures among coding-agent trajectories making explicit status claims, using environment state as ground truth. LLM judges over transcripts reached **AUROC of at most 0.65**, and 0.54 on the coding set, keying on confident language, while plain TF-IDF reached 0.83 and 0.95 ([arXiv 2606.09863](https://arxiv.org/abs/2606.09863)). This matters directly for design: Claude Code's `/goal` evaluator cannot run tools and judges the transcript ([docs](https://code.claude.com/docs/en/goal)). ImpossibleBench found an abort option cut GPT-5's cheating from 54% to 9% and o3's from 49% to 12%; Claude models cheat mostly by editing tests, which read-only tests block ([arXiv 2510.20270](https://arxiv.org/html/2510.20270v1)). Those models are from 2025. TDAD found that prompting for TDD made regressions worse (6.08% to 9.94%), while a code-to-test map cut them to 1.82%, on small open-weight models and with the authors evaluating their own tool ([arXiv 2603.17973](https://arxiv.org/abs/2603.17973)). A small vendor field record found a fresh-sandbox rerun caught 16 of 24 false claims, and a revert check caught 8 where tests passed without the change ([nomArmy](https://github.com/rayson-tech/nomarmy/blob/main/docs/findings.md)). **No controlled evidence shows that an independent reviewer agent reduces false completions, and no study compares test-first with test-after for agents.**

### Sandboxing and permissions: escapes keep going through trust handoffs

OS sandboxes are the strongest boundary available, and they keep being escaped the same way: the sandboxed agent writes something an unsandboxed process later trusts. CVE-2026-25725 let Claude Code create a missing settings file containing a host-side hook ([Cymulate](https://cymulate.com/blog/the-race-to-ship-ai-tools-left-security-behind-part-1-sandbox-escape/)). CVE-2026-39861 wrote through a symlink ([GitLab](https://advisories.gitlab.com/npm/@anthropic-ai/claude-code/CVE-2026-39861/)). Pillar's seven July bypasses cover Codex, Cursor, Gemini CLI and Antigravity through git arguments, Docker sockets, venv interpreters and agent-written tasks ([Pillar](https://www.pillar.security/blog/the-week-of-sandbox-escapes)). Claude Code's larger CVE count may reflect disclosure policy and research attention as much as weakness; the data cannot separate them, and no independent head-to-head of sandbox strength exists. Droid's tiers are explicitly "not operating-system isolation" ([Factory](https://docs.factory.com/cli/user-guides/auto-run)), and no independent evaluation of them was found.

Approval prompts are a weak boundary in practice. Anthropic reports users approve about 93% of prompts and that sandboxing cut prompts by 84% ([Anthropic](https://www.anthropic.com/engineering/how-we-contain-claude)). Its auto-mode classifier passes about 17% of overeager actions by its own count, against an independent 81.0% end-to-end false negative rate on deliberately ambiguous prompts, a difference the authors attribute to workload and to file edits falling outside the classifier ([arXiv 2604.04978](https://arxiv.org/abs/2604.04978)). Injection resistance has to be read per attempt count: Opus 4.7 goes from about 0.1% at one attempt to 5–6% at 100 ([Anthropic](https://www.anthropic.com/engineering/how-we-contain-claude)), and a meta-analysis of 78 studies, read only through a search extract, puts adaptive attack success above 85% against state-of-the-art defences ([arXiv 2601.17548](https://www.alphaxiv.org/abs/2601.17548)). The model layer is not a boundary.

### Hooks and extensibility: authority before consent is the recurrent hole

Check Point showed repository hooks and config overriding MCP consent and redirecting API traffic before trust confirmation ([Check Point](https://blog.checkpoint.com/research/check-point-researchers-expose-critical-claude-code-flaws/)), and Anthropic fixed this class by deferring project config parsing until after consent ([Anthropic](https://www.anthropic.com/engineering/how-we-contain-claude)). Cursor ran a hook from another tool's `.claude` file, CVE-2026-48124 ([Pillar](https://www.pillar.security/blog/the-week-of-sandbox-escapes)), and Amazon Q ran MCP commands from workspace config with no trust check, CVE-2026-12957, as reported secondhand ([CSA](https://labs.cloudsecurityalliance.org/research/csa-research-note-mcp-ai-coding-assistant-credential-theft-2/)). Skill registries show similar exposure: Koi found 341 malicious skills of 2,857 on ClawHub ([The Hacker News](https://thehackernews.com/2026/02/researchers-find-341-malicious-clawhub.html)). SKILL.md is a real shared core, found in 9 of 11 harnesses studied ([arXiv 2609.00006](https://arxiv.org/abs/2609.00006)), though overflow differs: Claude Code keeps every name and drops the descriptions of the least-used skills, while Codex shortens all descriptions and may omit skills ([Claude docs](https://code.claude.com/docs/en/skills); [Codex docs](https://learn.chatgpt.com/docs/build-skills)). Nothing measures how much hooks improve outcomes.

### Sessions: table stakes, with no outcome data

Fork, resume and spec flags are now common, and none has a controlled evaluation. Differences are documented, not measured. Claude Code's checkpoints skip Bash-only changes and most subagent edits and call themselves "not a replacement for version control" ([docs](https://code.claude.com/docs/en/checkpointing)), and its teammates do not survive resume. `droid exec` offers a headless `--fork` and `--use-spec` ([docs](https://docs.factory.com/cli/droid-exec/overview)). Fresh starts have practitioner support from both Cursor and Anthropic's project-scale runs, without a control. The one useful outcome-adjacent finding is that a missing fact produces wrong work rather than absent work: only 37% of pooled trials said they were blocked, ranging from 100% on Opus to 0% for some pairings ([arXiv 2608.16630](https://arxiv.org/pdf/2608.16630)).

The most useful evidence in this list is the failure-mode kind, because each failure is cheap to fix and easy to test. Half of OpenCode's deficit on one model came from output-cap truncation, where Claude Code prompts the model to continue ([arXiv 2610.04433](https://arxiv.org/abs/2610.04433); [VentureBeat](https://venturebeat.com/orchestration/a-coding-agents-harness-can-triple-its-cost-without-making-it-more-accurate-study-finds)). In Arjmandi's study, 22 of 81 runs cancelled at the wall clock already had a passing patch. DeLM's empty patches came from a parent waiting on a killed child, and Vats and Golev found idle loops, max-turn exits and verify failures characteristic of specific harnesses. Average gaps between harnesses are noise at current sample sizes. **Failure-mode gaps are real, specific and fixable, and they are the honest basis for "this harness is better."**

## ox leads on first-request weight and is unproven on everything a long run touches

ox's fixed floor is its one reproducible lead. Its recorder test gives 2,070 tokens for a coding prompt, against Codex 10,334, Hermes 11,757 and Claude Code 16,734 in clean setups, on a stand-in model server, by characters over four (`bench/token-overhead/README.md`). The Claude Code figure agrees with the roughly 16.6K in independent reporting, which lends the method credibility, although ox's owner ran it. A re-run of `bench/compare-hermes.mjs` on the audit day gave about 2,350 against 10,924, confirming the ratio. The speed claim did not survive: one cold run measured 1,680 ms against 3,741 ms, so the old "13x faster" figure was removed from the README during this research. In the only same-model four-way run, on a 3B local model, every agent scored 0/9 and ox made 58 requests and spent 181,544 input tokens against Codex's 18 and 53,541 (`bench/h2h/RESULTS.md`). Several tempting projects should wait. Hashline or apply models lack frontier-model evidence, and a recall benchmark score would be a poor marketing basis given what LOCOMO's critics document. An LLM reviewer as a merge gate has no outcome support, and judges perform poorly at this. More swarm features, model routing and further code-graph work should wait for item 3, since routing can cost three times more when done badly and graph value is unmeasured. ox's non-coding surface (mail, voice, studio, mesh) is irrelevant to a harness comparison, and it adds test burden on a repository whose static scan found 62 source files with no test reference, and no sign of CI on ordinary pushes.

One priority call could reasonably go the other way. Item 3 could come first on the argument that measurement should drive everything. I place 1 and 2 ahead because the first is a confirmed hole, the second would otherwise distort the experiment's cost figures, and both take days, not weeks.

## Conclusion

The question "which harness is best" has quietly become a question about measurement. Pass-rate gaps sit inside rerun noise at the sample sizes anyone publishes, and even the reference suite's tasks are contested, so a vendor's first place is mostly a statement about configuration. Cost gaps, by contrast, are often large enough to resolve with small samples. That makes cost per solved task, reported with failure causes, the most defensible public claim any harness can make, and it happens to be where a low-floor harness has its best chance. It also carries a real risk for ox: a low floor multiplied by many requests is not cheap, and in the one comparative run ox has, which every agent failed, it made three times Codex's requests.

ox's most useful position is less "better than Claude Code" and more the first harness to publish, on a capable model, its own ablations, including where a feature did nothing. Factory's study shows what a single unablated number buys, and the literature shows how little it can establish. Publishing what memory, masking, narrowing and proof each contribute, with confidence intervals and trajectories, would be a claim rivals have not made and one a small project can afford. The fixes that landed during this research show the audit-to-commit loop works at speed; the discipline still missing is measuring each fix before the docs describe it as a gain.
