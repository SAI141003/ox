# Users want control, not more agents

The evidence says customers mostly want **control over a coding agent they already use**, not more autonomous agents. Across agent issue trackers, the most-upvoted requests are open configuration standards (AGENTS.md alone has 6,687 reactions), freedom to pick any model, the ability to run on any machine, usage and account visibility, plan-then-undo, and hooks. Requests for model races, side-by-side compare, agent "companies" or language porting barely show up. Outside coding, adoption is real where a feature does one small, frequent job well: dictation (Wispr Flow reports 70% 12-month retention), bot-free meeting notes (Granola at a $1.5B valuation), phone approvals for agents (544 reactions before Codex shipped it), and editing or enhancing existing media (55% of creators). Open-ended products have struggled: ChatGPT Agent reportedly lost about 75% of its weekly users and OpenAI closed its Atlas browser. ox already has most of the demanded coding basics: AGENTS.md, plan mode, ACP, checkpoints, any model, and approvals on the phone. To beat its rivals it should change what it leads with, not what it builds. It should **lead with "the coding agent that proves its work, on any model"**, push the notch, phone and dictation as ways to supervise that agent, cut Studio and automations down to a few proven recipes, and treat race, office, org and port as supporting features rather than headlines. The most urgent fix costs nothing in features. The README tells Mac users to right-click › Open the unsigned app, which **macOS Sequoia no longer allows**, so the first-run path currently ends at a "Move to Trash" dialog.

## The most-demanded features are about controlling the agent

Usage data shows what people delegate. In Anthropic's internal study, **55% of engineers use Claude Code daily for debugging**, 42% for understanding code and 37% for building features. The share of transcripts spent "implementing new features" rose from 14.3% to 36.9% in six months ([Anthropic](https://www.anthropic.com/research/how-ai-is-transforming-work-at-anthropic)). In Anthropic's study of 500,000 interactions, web and UI work dominates: JS/TS is 31% and HTML/CSS 28% ([Anthropic](https://www.anthropic.com/research/impact-software-development)). Across all developers, the jobs people least want an AI to do are deployment (75.8% "don't plan to"), project planning (69.2%) and committing or reviewing code (58.7%) ([Stack Overflow 2025](https://survey.stackoverflow.co/2025/ai)). Demand for `ox build`'s tests-first proof and `ox pr`'s CI loop will therefore come from power users. The mainstream entry point is "fix this bug", and ox has no dedicated flow for it.

Issue-tracker reactions show what users ask for. The top-reacted issue in any agent repository is Claude Code's **"Support AGENTS.md" at 6,687 reactions** ([#6235](https://github.com/anthropics/claude-code/issues/6235)), followed by ACP ([550](https://github.com/anthropics/claude-code/issues/6686)) and skills on Gemini CLI and OpenCode. Model freedom comes next. "Support for OpenCode and Max plan" has **1,414** reactions ([#17118](https://github.com/anthropics/claude-code/issues/17118)), and nearly every top Cursor forum request asks for a specific model, such as GLM 4.5 with 404 likes ([Cursor forum](https://forum.cursor.com/t/add-glm-4-5-as-a-cursor-auto-model/123631)). "Run it anywhere" is the third cluster: a Codex Linux desktop app has **1,464** reactions ([#11023](https://github.com/openai/codex/issues/11023)), remote development 878 and remote control 544. Accounts and cost form the fourth: multiple accounts in Claude Desktop has **1,147** reactions ([#18435](https://github.com/anthropics/claude-code/issues/18435)), and users protested when Codex removed its context meter (253, [#23794](https://github.com/openai/codex/issues/23794)). After those come plan mode and undo (Codex "/undo back" 538, plan mode 506) and extensibility (Codex event hooks 688, subagents 413).

Users also push back when a product takes control away. Cursor users asked how to turn off the new Review page and how to make Ask the default mode instead of Agent ([Cursor forum](https://forum.cursor.com/t/how-can-i-change-default-chat-mode-as-ask-not-agent/53850)). Codex users asked for its background daemon to be opt-in (204, [#48195](https://github.com/openai/codex/issues/48195)). Users want to see the diff and keep the off-switch.

The counter-signal matters just as much. Parallel agents, model races, side-by-side compare, scheduled runs and task boards **do not appear in the top 20 of any tracker**. The closest requests are OpenCode "Agent Teams" (190) and Cursor's "R1+Sonnet combination" (70). Only **17.3% of agent users say agents improved team collaboration**, the lowest benefit in the survey ([Stack Overflow 2025](https://survey.stackoverflow.co/2025/ai)). This does not show these features are useless; an absence of requests is weak evidence. It does show they will not bring users in. They work as proof machinery behind the main pitch. ox's race now picks its winner by evidence, which turns a novelty into a better selector for `ox build`.

The quality of the work still matters most. **66% of developers name "almost right, but not quite" as their top AI frustration**, and 46% distrust AI accuracy ([Stack Overflow 2025](https://survey.stackoverflow.co/2025/ai)). In JetBrains' 2025 survey, code quality (23%) ranks well above privacy (13%) as a concern ([JetBrains](https://blog.jetbrains.com/research/2025/10/state-of-developer-ecosystem-2025/)). ox's "checks its own work" claim speaks directly to the largest complaint. That is why it should be the headline, and why the README's honest admission that the head-to-head run "passed nothing under any agent" on a 3B model needs a re-run on a frontier model soon.

## Companions win by supervising the agent, not by doing tricks

Desktop and voice AI succeeds when a feature is small, frequent and reliable. In TidBITS' survey of Apple enthusiasts, the Apple Intelligence features with real impact were Photos Clean Up (25.8%) and photo search (23.9%). Image Wand reached 1.6% and Genmoji 9.1%, and half of all features had impact for fewer than 10% of users ([TidBITS](https://tidbits.com/2025/06/20/do-you-use-it-apple-intelligence-sees-weak-adoption/)). The notch-app category points the same way. Boring Notch users file far more issues about polish (Now Playing breaking after macOS updates, wobbly animations, the notch showing in fullscreen) than requests for new widgets ([boring.notch](https://github.com/TheBoredTeam/boring.notch/issues/417)). For OX Island, staying out of the way is a feature. Fullscreen and external-display hiding, an animation toggle, and alert sounds that fire only when an agent needs input (Vibe Notch's users ask for exactly that) matter more than the inbox card, service cards or draw-on-screen.

The island's unique job is supervising agents. Vibe Notch reached 2,527 stars doing notch approvals for Claude Code alone, and a paid rival, Vibe Island, now covers Claude Code, Codex, Gemini CLI and Cursor ([vibeisland.app](https://vibeisland.app/claude-code/)). ox's advantage is breadth: every agent, on every machine, with the same approvals on the notch, the phone and in messaging. The **usage meter** is the most strongly supported island addition, since it answers both the limits complaint (726 reactions) and the multi-account requests (1,147). `docs/FEATURES.md` lists it as not built, even though ox already records the usage.

The phone is where the gap is clearest. Before Codex shipped Remote Control, its request drew 544 reactions from users who had been rigging Tailscale and SSH ([#9224](https://github.com/openai/codex/issues/9224)). Claude Code's official remote control sends push notifications but has **no Live Activity and no standalone app** ([Claude Code docs](https://code.claude.com/docs/en/mobile)), and push delivery has broken before ([#60208](https://github.com/anthropics/claude-code/issues/60208)). Third-party apps split the job: Codync only monitors, and Forge Remote approves ([App Store](https://apps.apple.com/dk/app/forge-remote/id6760141378)). ox's iOS target already includes ActivityKit. Lock-screen approve and deny for any agent, with a Telegram fallback when push fails, is a feature neither OpenAI nor Anthropic offers.

Dictation is the voice feature with proven daily retention. Wispr reports that retained users produce over half their typed characters by voice, and reports 70% 12-month retention ([Sacra](https://sacra.com/c/wispr); [UC Today](https://www.uctoday.com/?p=748171)). Its weak points are exactly where ox is strong: it is cloud-only, takes screenshots of the active window for "context", and uses about 800 MB of RAM at idle ([Voibe](https://www.getvoibe.com/resources/wispr-flow-review/)). Open-source users mainly complain about reliability, such as Handy dropping the first character on paste ([Handy](https://github.com/cjpais/Handy/issues/429)), and they ask for system-audio capture and speaker labels ([VoiceInk](https://github.com/Beingpax/VoiceInk/issues/31)). Those requests lead naturally to meeting notes. Granola's rise to **$1.5B on bot-free capture** ([Reworked](https://www.reworked.co/digital-workplace/granola-raises-125m-launches-enterprise-context-tools/)) shows a local, bot-free call-notes feature built on ox's speech engine and brain is the strongest new voice product available. A wake word is the opposite case. 49% of users don't realise assistants listen continuously, and 31% have privacy concerns ([Secure Data Recovery](https://www.securedatarecovery.com/blog/smart-device-privacy-concerns)), so hold-to-talk should remain the default.

On Windows, the demand signal is weaker than for Linux. A Codex Windows installer drew 265 reactions, against 1,464 for a Linux desktop app and 655 for Claude Desktop on Linux ([#65697](https://github.com/anthropics/claude-code/issues/65697)). ox's Tauri desktop already runs on Linux, so a Linux build is likely cheap. Note that this is an inference about cost, not a measurement.

## Outside coding, the winners are scoped jobs

Most of ox's non-coding features face the same pattern: the general version fails and the job-shaped version survives. ChatGPT Agent launched with about 4M weekly paying users and fell below 1M because users "couldn't figure out what to do with it" ([The Decoder](https://the-decoder.com/chatgpt-agent-reportedly-lost-75-of-its-users-because-nobody-knew-what-it-was-actually-for/)). OpenAI then moved its browser into the main app plus a Chrome extension. Meanwhile Codex plus ChatGPT Work reached 10M weekly users within two weeks on named jobs such as month-end reports and scheduled tasks ([TNW](https://thenextweb.com/news/openai-agents-10-million-chatgpt-work)). Trust is also shifting: **32% of AI users have let an agent act without final approval** and 36% have given one email access ([Digital Applied on Menlo](https://www.digitalapplied.com/blog/ai-agent-access-permissions-consumer-survey-statistics-2026)). ox's confirm-before-buy, pay or send is a trust advantage, not friction. `ox browse` should stay fast and task-named, and should not grow into an open-ended "agent mode".

Automations show the same pattern. Self-hosted, messaging-first agents have huge developer interest: OpenClaw gained about 356K stars in three months and Hermes about 230K ([gradually.ai](https://www.gradually.ai/en/hermes-agent-statistics/)). Yet in 336 documented OpenClaw examples, the largest category was configuring the agent itself ([Claude Market](https://claudemarket.ai/blog/openclaw-use-cases-336)). The typical first flow is a morning briefing, reminders and an email summary, delivered on Telegram ([tldl.io](https://www.tldl.io/blog/openclaw-use-cases-2026)). n8n's templates are mostly AI plus business plumbing: the most-used nodes are Code, Set, HTTP and Google Sheets ([n8n-pulse](https://n8n-pulse.gui.do/templates)). ox should therefore ship a few starter flows that work on install (morning briefing, PR digest, failing-CI alert, weekly usage report) and finish the schedule page's missing edit, delete and history. A larger node catalogue can wait.

The agent org and office have the weakest demand evidence of anything ox builds. No "AI employee" vendor publishes retention, and a hands-on review concludes these products "are really sophisticated automations" ([TeamDay](https://www.teamday.ai/blog/ai-employees-market-map-2026)). Consumers are also moving back toward collaboration: augmented conversations rose to 52% of Claude.ai use ([Anthropic Economic Index](https://anthropic.com/research/economic-index-primitives)). The office's appeal is real, but it is visibility and fun. Pixel Agents earned 9.8k stars for one agent on one machine. The pitch that fits the data is "see every agent on every machine at a glance".

Memory and research pass the test because ox's design matches the stated complaint. Users want to see and control what an assistant remembers ([UGA Grady](https://grady.uga.edu/research/ai-never-forgets-exploring-users-perceptions-of-ai-memory-and-chatgpts-memory-feature/)), and ChatGPT lacks per-memory control ([eWeek](https://www.eweek.com/news/grok-can-remember-conversations-now/)). The ox brain stores each memory as a markdown file, which answers that complaint directly. Deep research comes with ChatGPT, Gemini and Perplexity, so by itself it won't win users. What none of them offer is research saved into a local, linked vault that the next coding task reads.

Studio needs the sharpest refocus. **The largest creative job is improving existing media (55%), not generating new images (52%)**, and the top barriers are cost (38%) and unreliable output (34%) ([Adobe](https://news.adobe.com/news/2025/10/adobe-max-2025-creators-survey)). The most heated complaints across Runway, Kling, ElevenLabs and Descript are credits burned on failed generations and billing friction ([vantaige.io](https://vantaige.io/ai-tool/runway); [G2](https://g2.com/products/elevenlabsio/reviews?page=5)). Standalone text-to-image is being absorbed by ChatGPT and Gemini: Midjourney fell from the top 10 to #46 ([a16z](https://a16z.com/100-gen-ai-apps-6/)). ox's local SD-Turbo will not beat GPT Image or Nano Banana on quality. It can win on free retries, privacy and no setup, which is the same appeal that makes Draw Things preferred over ComfyUI's "package hell" ([InsiderLLM](https://insiderllm.com/guides/stable-diffusion-mac-mlx/); [alanbonnici](https://www.alanbonnici.com/2026/07/comfyui-and-package-hell.html)). Developers' visible needs are app icon sets, store screenshots, social cards and demo videos ([Vercel community](https://community.vercel.com/t/pixelle-ai-icons-and-graphics-generator-that-makes-indie-apps-look-professional/36196)), and they want generation callable from the coding agent, as Draw Things now offers over MCP. Studio should be repositioned as "make your app's assets and demo video from inside the agent", with cost shown before any cloud run.

## A first-run cliff and unclear plan wording put adoption at risk

The quickest adoption win is fixing the install. ox's README tells Mac users the app "is not notarized by Apple yet: the first time, right-click OX › Open". **macOS Sequoia removed the Control-click Gatekeeper bypass, and 15.1 shut it off entirely**. Open-source projects such as OpenSCAD were caught by the change ([Hackaday](https://hackaday.com/tag/appledrm/)). An unsigned app now shows a dialog that offers only "Move to Trash" or "Cancel" ([Electron docs](https://ayakael.net/mirrors/electron/commit/7932e28aa2a974f39019770fc3f8e77a8276cdaa)). Most Mac users run Sequoia or later, so they hit a dead end at their very first step. The stopgap is to rewrite the README so the steps are: open once, then go to System Settings › Privacy & Security › Open Anyway, with `xattr -dr com.apple.quarantine /Applications/OX.app` as the terminal alternative. The real fix is Developer ID signing and notarization in CI, which costs $99 a year. Homebrew also dropped support for casks that fail Gatekeeper checks from Sept 1, 2026 ([lemmy](https://lemmy.4d2.org/post/1941658/2526816)). The terminal path is exempt from notarization ([Bastion docs](https://docs.bastion.tech/devices/apple/signing-notarizing)), which makes `npm i -g` or a Homebrew formula the lowest-friction route today.

Pricing is the second trust lever. Every move from flat to metered billing in this category (Cursor in June 2025, Claude weekly caps in August 2025, Copilot AI Credits in June 2026) set off backlash. In Cursor's case it ended in a public apology and refunds ([TechCrunch](https://techcrunch.com/2025/07/07/cursor-apologizes-for-unclear-pricing-changes-that-upset-users/); [Visual Studio Magazine](https://visualstudiomagazine.com/articles/2026/08/07/copilot-credit-complaints-keep-coming-too-expensive-to-use.aspx)). Cost blocks agent adoption for 53.3% of developers, and "prohibitive pricing" is the second most common reason they abandon a tool ([Stack Overflow 2025](https://survey.stackoverflow.co/2025/)). Because ox charges nothing and passes inference through, it avoids the most-hated pattern, as Cline and OpenCode do. It should state "you pay your provider; ox takes nothing" plainly and show spend in real time. One wording issue matters here. The README's first line says ox "runs on the AI you already pay for (Claude, ChatGPT, Cursor)", while the setup section correctly says Claude needs an API key because Anthropic reserves Pro/Max logins for its own apps. The headline should name ChatGPT plans and API keys, so no reader assumes their Claude subscription works in ox.

Privacy works as a gate rather than a reason to adopt. 81.4% of developers worry about data security when using agents, and security or privacy is the top reason they drop a tool. Yet 28.2% say their company's IT rules block agents outright ([Stack Overflow 2025](https://survey.stackoverflow.co/2025/ai)). "No account, no telemetry, local models" keeps ox from being rejected, especially in regulated companies. Users still choose on quality, so privacy belongs in the reassurance line, after the proof claim.

## Conclusion

The research puts ox in a different position from where its feature list suggests. ox is not short of features. It already has nearly every coding basic users vote for, and several, such as AGENTS.md, ACP, plan mode, checkpoints and phone approvals, are what rival trackers are still asking for. The weakness is **presentation and focus**. The README opens on 15 surfaces of roughly equal weight, while the evidence says users adopt one sharp job and discover the rest later. Rivals are converging on the same agent features, so ox's lasting edge is a small, provable core (verified work on any model) plus a supervision layer that spans every agent and machine: the notch, the phone, Telegram and the office. Rivals tied to one model or one vendor's agent cannot easily match that.

A second point is less obvious. Several features with weak standalone demand become valuable once they serve the core. Race becomes the selector that makes `ox build`'s proof stronger. Research and meeting notes feed the brain that the next coding task reads. The office becomes the visual status of the supervision layer. Studio becomes a tool the agent calls to make an app's icons and demo video. ox does not need to delete features. It needs to stop presenting each one as a product.
