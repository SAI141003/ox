## Update, end of 2026-11-03 (read this first)

Releases: v0.1.8, v0.1.9 and v0.1.10 are published; v0.1.7's tag is on GitHub with a partial release from a failed run.

Found by running the real downloads, not by reading code:
- OX Island crashed 0.3 s after launch on every Mac that installed a release before v0.1.10: SwiftPM's `Bundle.module` looks beside the .app and at the CI build folder, and calls fatalError. `OxResources` replaces it. A dev machine never shows this, because its build folder exists: test the CI-built file.
- "Starting ox…" stuck: a failed load within the retry wait was dropped. Reproduced with the real `OxApp` and a stub for `OX_CLI` (a dead address twice, then a live one); fixed in `recover()`.
- Commits 35668d1 and ed32a8c explain these two wrongly. Their messages stand in history; the later commits correct them.

Testing traps:
- OX Island writes `~/.ox/island.json` under the real home, whatever `$HOME` says. A throwaway `HOME` does not isolate it, and starting a second island disturbs the running one.
- `/ox/mesh` falls back to the real node on the fixed control port. `OX_MESH_PORT` + `OX_MESH_PROXY_PORT` run a second app with its own node; start it and let its node come up before trusting the list.
- Editing the checkout restarts the owner's app server when OX.app runs from it.

Not understood: what writes `~/.cache` and `~/.fontconfig` during the Ubuntu unit run (daemon 16 now ignores those two folders).
